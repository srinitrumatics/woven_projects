## Phase 0: Research

**Status**: Complete — see [research.md](./research.md)

Key decisions from codebase inspection:

1. **All table infrastructure is already in place**: `SortableHeader`, `useSortableData`, `Pagination`, `useResizableColumns`, `displayCell()`, and sticky-column patterns are all fully implemented and consistent across existing sub-tabs. No new primitives needed.

2. **Default sort is `"desc"` everywhere and must change to `"asc"`**:
   - `productSortDirection` in `page.tsx:968` — `useState<SortDirection>("desc")` → `"asc"`
   - `orderSortDirection` in `page.tsx:977` — `useState<SortDirection>("desc")` → `"asc"`
   - `useSortableData` init in `FulfillmentsTab.tsx:48` — `direction: 'desc'` → `direction: 'asc'`
   - `useSortableData` init in `ReturnsTab.tsx:48` — `direction: 'desc'` → `direction: 'asc'`

3. **Salesforce field mapping gaps to fill** (confirmed by inspecting page.tsx data mappings):

   | Object | Missing TypeScript field | SF source field |
   |--------|--------------------------|-----------------|
   | ProposedProduct | `status` | `item.Status__c` |
   | ProposedProduct | `brandName` | `item.gtherp__Brand_Name__c` |
   | ProposedProduct | `qtyShipped` | `item.Qty_Shipped__c` |
   | Order | `proposalRequested` | `order.Proposal_Requested__c` |
   | Order | `transferOrder` | `order.Transfer_Order__c` |
   | CustomerQuote | `proposalId` | `cq.Proposal__c` |
   | CustomerQuote | `proposalName` | `cq.Proposal_Name` / `cq.Proposal__r?.Name` |
   | SalesOrder | `salesOrderId` | `so.Id` (parent is the root record) |
   | SalesOrder | `proposalId` | `so.Proposal__c` |
   | SalesOrder | `proposalName` | `so.Proposal_Name` / `so.Proposal__r?.Name` |
   | ShippingManifest | `proposalId` | `sm.Proposal__c` |
   | ShippingManifest | `proposalName` | `sm.Proposal_Name` / `sm.Proposal__r?.Name` |
   | ShippingManifest | `boxLength` | `sm.Case_Length__c` |
   | ShippingManifest | `boxWidth` | `sm.Case_Width__c` |
   | ShippingManifest | `boxHeight` | `sm.Case_Height__c` |
   | Invoice | `proposalId` | `inv.Proposal__c` |
   | Invoice | `proposalName` | `inv.Proposal_Name` / `inv.Proposal__r?.Name` |
   | Invoice | `purchaseOrderName` | `inv.Purchase_Order_Name` |
   | RMA | `proposalId` | `r.Proposal__c` |
   | RMA | `proposalName` | `r.Proposal_Name` / `r.Proposal__r?.Name` |
   | CreditMemo | `salesOrderName` | `c.Sales_Order_Name` |
   | CreditMemo | `proposalId` | `c.Proposal__c` |
   | CreditMemo | `proposalName` | `c.Proposal_Name` / `c.Proposal__r?.Name` |

4. **Fulfillment sub-tab order**: Currently `quotes → sales → invoices → shipping`. Required: `quotes → sales → shipping → invoices`. Fix: reorder the `<button>` elements in `FulfillmentsTab.tsx` and ensure the default `activeFulfillmentTab` in page.tsx stays `"quotes"`.

5. **Returns sub-tab order**: Current order is RMAs, Credit Memos, RTVs, Debit Memos (for unrestricted users) and RMAs, Credit Memos (for Customer/NSO). No reordering needed — the customer-facing tabs are already RMAs → Credit Memos. The spec only lists those two because it describes the customer-facing view.

6. **`useSortableData` `key` value for default sort**: The spec says "Record ID ascending" — the Record ID maps to the `name` field in every sub-tab (e.g. `name` = Order Name / Quote Name / etc.). Existing sort key `'name'` is already correct; only direction needs to change.

7. **Column renaming**:
   - `manufacturerDBA` field in `ProposedProduct` is mapped from `item.Manufacturer_DBA__c`. The new `brandName` field maps to `item.gtherp__Brand_Name__c`. These are **two different SF fields** — `brandName` is added as a new field alongside the existing mapping; the "Manufacturer DBA" column header is **replaced** by "Brand Name" in the component rendering `brandName` instead of `manufacturerDBA`.
   - Orders: `"Customer Order"` → `"Customer Order #"`, `"CPO Date"` → `"Customer PO Date"`
   - Customer Quotes: `"Issue Date"` → `"Issued Date"` (line 146 in FulfillmentsTab.tsx)
   - Invoices: `"Customer Orders"` (line 410, plural error) → `"Customer Order #"`
   - RMA: `"RMA Type"` → `"Type"` (field stays `rmaType`)
   - Credit Memo: first column header `"Credit Memo"` → `"Credit Memo #"`
